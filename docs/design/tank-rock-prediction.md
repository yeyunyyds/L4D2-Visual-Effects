# Tank 石头预测：正式功能整理设计

## 提交状态

本功能分支基于正式 main `1654a7ee062f5eb8aedad0c4ed65c9acd7dd86de`（0.7.4）整理。实验工作区基于 0.7.2，未直接覆盖正式源码；此前 demo 的刀石、诊断及采集代码不进入本分支。

原功能分支仅整理源码；0.8.0整合阶段已完成28组原生回归、Windows x86构建和用户验收。

4. Tank 石头预测 [关/开]

## 正式运行路径

- 复用已验证 `VClientEntityList003`、RecvTable 字段读取、实体 handle/serial、相机和 Present/ImGui 路径。
- 全实体发现仍为 200 ms，不因本功能启用 50 ms 完整战斗采样；已有 Tank 行为模块的 50 ms 机制保持独立。
- 专用类 CTankRock/TankRock 可直接接纳；共享 CBaseCSGrenadeProjectile 只有 thrower/owner 的完整身份解析到 Tank 才接纳。共享类本身不足以判定石头。已知非 Tank thrower 不被 owner 覆盖。
- 已发现的石头每相机回调只定向读取；同毫秒回调去重，前后核对 entity 地址与 serial。临时读取失败清理该石头运动状态，不调用未经验证的地址/字段。
- 挂接或父关系未知时不把 m_vecOrigin 当世界坐标；飞行中优先用已验证类型的速度字段，否则用相邻有效观测差分。
- 保留当前/前一观测所需状态，不保留历史样本队列。相同位置不制造新观测；超过 250 ms 不显示旧轨迹，超过 2 秒未见回收。最多 64 个实体，每条轨迹最多约 41 个点。
- 固定内部重力 320 units/s²，固定半尺寸 16 的假定轴对齐箱。数值来自此前模型选择，不代表读取到的引擎参数或真实碰撞体。正式菜单不暴露重力、碰撞箱、前摇等实验参数。
- 不使用未验证的模拟时间代理。石头样本使用观测到达时间；不声称等同网络更新频率或服务器时钟。原正式 Tank 模块自己的模拟时间读取逻辑不作改动。
- 预测为抛物线，每 25 ms 分段。静态世界接触预测复用独立 Trace Binding，最多 3 秒，每 50 ms 轮询一个石头，每轮最多 64 次查询。
- 落点区分箱中心与表面接触点：线截到中心位置，红圆画在接触表面。只要无有效交点、接口验证失败、起点在固体内或结果过期，就不画落点圆；不再用理论轨迹终点代替落点。
- 地图 Trace 不可用时，实体追踪和纯轨迹继续工作。模块异常只停用本功能；总开关关闭会清理状态，可重新开启。地图切换、断开和实体复用清理旧状态。

## 画面

仅显示轨迹线和半透明红色落点圆。删除当前位置圆、速度箭头、未来时刻数字、身份/置信度文字、误差表、候选调试标记和刀石提示。

默认轨迹为绿色、80% 不透明度、2 px；落点圆半径为世界空间 32 units、红色、50% 不透明度。圆仅是可见性标记，不代表伤害范围。边界处无法完整投影圆面时可用小屏幕圆标示同一个有效交点，绝不退回未知未来位置。

复用现有 Tank 样式模块中纯相机的 OverlayGate 做失焦/Esc/转动视角恢复门控，不依赖 Tank 行为总开关。仍使用原有私有 ImGui 上下文，菜单关闭时允许绘制 overlay；不添加 D3D Hook。原菜单 addon/精调接口保持不变。

## 配置与默认值

新增 `tankRockPrediction` 命名空间：enabled=false，trajectory=true，landingCircle=true，horizonMs=500，color=0，opacity=0.8，lineWidth=2，landingRadius=32，landingOpacity=0.5。

默认关闭；用户在新正式命名空间中明确保存 enabled 后按该值恢复，与现有正式功能保存逻辑一致。旧 demo 的 tankRockDisplay、tankRockMelee、实验 A/B/C 开关都不迁移、不启用本功能。类型错误及越界显示值使用默认/受限值；保存只写正式字段。

保存不会删除用户磁盘上的旧 JSONL 文件，但本功能不会打开或追加它们。其他现有功能及其基础日志不受本次整理影响。

## 不进入正式分支的内容

- 刀石范围、射线相交、前摇、时间偏移、攻击输入/自动攻击。
- JSONL 数据队列、后台写入、预测误差回填、采样/延迟指标、数据分析脚本。
- RecvProxy 指令转储、浮点存储探针、模型和候选实体诊断列表。
- 观测重力拟合、实验参数开关和 demo 页面。

这些不通过运行期开关隐藏，而是完全不包含在正式模块的 include/调用路径中。原实验工作区与已发布 demo 包保持独立，供需要时研究。

## 文件及合并触点

新增 rock_identity.hpp / rock_prediction.hpp / rock_landing.hpp（纯算法）、rock_settings.hpp（配置）、rock_runtime.hpp（游戏读取）、rock_ui.hpp（菜单/显示）。

最小共享修改包括：Record.thrower、公共速度/thrower 白名单、只对石头候选补充读取；Trace Binding 支持独立实例和对称 AABB；NativeHud 增加 overlay 回调；plugin.cpp 接入采样、菜单和配置；hud_runtime.hpp 接入显示门控。没有修改 Tank 序列表、Tank 行为算法、模型拉伸或喷漆协议。

与另一个测试分支合并时重点检查：

1. plugin.cpp 中保留双方 onFrame/保存/加载入口，确保 Tank 行为预测与石头预测都在。
2. NativeHud 保留 configureAddon/configureAdjustment；若另一分支也增加 configureOverlay，应统一组合绘制回调，不能后一次配置覆盖前一次。
3. hud_runtime.hpp 保留已有画面备份/恢复、Tank 绘制、设备 Reset 逻辑。
4. 合并菜单时保留 page 700/701 与 action 750～759，检查另一分支是否占用相同 ID。
5. 合并默认 JSON 时保持所有既有用户样式值，只新增 tankRockPrediction。
6. 若另一分支也调整 Trace/实体读取，以共享的已验证 ABI 和完整身份检查为准，不复制整份旧实验头文件覆盖。
