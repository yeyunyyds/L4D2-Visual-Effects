## 使用

「邦友的酒 → 实体分类 → 进入手动识别」和「实体缩放与拉伸 → 准星识别与调整」共用同一套识别逻辑：

- **场景本体**：对准目标，点击手动识别。请求交给游戏线程，菜单显示等待与结果；通常下一游戏帧完成。优先角色本体，不让爪子或持有模型抢走本体。
- **切换候选**：可明确选择识别到的武器、附属模型，再手动开关或进入形变参数。附属选择显示提示，不把它伪装成角色本体。
- **本机手持**：切换模式后手动识别，优先列出第一人称 ViewModel，随后列出本机 active weapon 及可验证关联的持有模型；解决第一人称模型使用独立投影、骨骼附件没有独立网络姿态的问题。这里只选择配置类型，不声明这些候选被世界射线直接命中。
- 切图清除结果；重新识别失败不会继续操作旧结果。清除或切换模式会取消尚未执行的请求；已在游戏线程执行的同步射线完成后，其旧结果会被忽略。请求超过1.5秒未完成会提示重试。

## 目标选择与边界

优先使用经校验的 EngineTraceClient003 / TraceRay（与现有喷漆使用同一套已验证的 x86 Ray/Result 布局），场景识别使用 MASK_SHOT，排除本机玩家和已验证归属的持有实体。回传实体必须与当前实体目录的完整句柄、序列号和地址一致；命中墙体或不能映射的碰撞对象时停止，不静默穿过它选择后面的目标。

可见性、健康与碰撞包围体元数据由基本实体目录读取，不再依赖 Tank 预测总开关。按视线与有效身体包围体求交，优先原生射线命中与最近的身体范围，移除原来的48单位近距离排除。角色身体不因视角俯仰倾斜；支持坐姿、原点在脚下、原点离开视野但身体仍被瞄准的情况。原生射线命中明确、但网络附件姿态不可解析或 dormant getter 缺失时（明确休眠仍排除），仍可选择其已确认类型。

武器归属综合 owner、weaponOwner、moveparent、m_hCombatWeaponParent / ViewModel.m_hWeapon 与角色 activeWeapon / viewModel 反向引用，完整句柄匹配、父链最多16层并拒绝循环。多个角色对同一武器的归属冲突不强行归给某一角色；历史投掷者不等于当前持有者，丢下的侏儒等物品继续作为场景物品。

缺少碰撞包围体的几何候选会标记估算，使用有限的保守身体/道具包围体。碰撞体、客户端命中盒与 MOD 的可见轮廓不保证完全一致；非碰撞模型的候选仍是几何估算，需要核对类型。未知求生者/特感角色拒绝生成设置，不再产生 v:-1。

只在用户手动请求时执行射线，HUD 渲染回调只排队和消费不可变结果，不发起 Source 调用或模型重绘。接口、布局或输出校验失败会拒绝识别；输出校验异常时停止当前地图的场景识别。本机手持模式不使用世界射线。首次场景射线操作后固定本 DLL 到游戏进程结束，以保护同步过滤器回调生命周期；更新需要完全退出游戏。

## 设置一致性与旧配置

特感按8种类型、求生者按8名角色控制；两个识别入口与分类菜单指向同一项。内建道具采用与分类菜单一致的 t:类名规则，动态类型仍用 c:ClassID:类名防止身份混淆。

形变旧配置中内建道具的 c:ClassID:类名覆盖会在加载时合并到 t:类名，保留此前有效的覆盖值并清除重复项；已有显式特感角色规则优先保留。无效角色键会被清理。迁移仅改变内存设置，正常保存时写回；不会自动打开形变总开关。识别到角色后作为范围实验来源时，也沿用同一个角色/类型身份。

## 已记录的提醒要求

范围提醒入口归入「Tank 预测 → 显示内容 → 攻击范围内提醒」。新配置中攻击范围红线默认开，进度条红底、填充、描边默认关，Tank 总开关仍默认关。旧配置若已显式设置 warnRange=false 会保留用户值，缺少字段时采用新默认。
