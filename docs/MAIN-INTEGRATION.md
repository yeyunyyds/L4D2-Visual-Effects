# 0.8.0 主线整合与验收

远端 main 基准为 `1654a7ee062f5eb8aedad0c4ed65c9acd7dd86de`（正式0.7.4）。在独立仓库的本地 main 合并：

- 实体形变、preview2/3 的菜单及 Tank 范围提醒，以及共用识别修复 `4c56a77`。
- `feature/tank-rock-prediction` 的 `03543e0db569ee150d8c82d1f950ed8469675353`。

整合测试源码提交为 `922d02e`，用户验收通过后以0.8.0发布。main保留源码与文档，zip和Release提供安装包及配套源码。

## 合并决策

保留双方的菜单、配置读写、onFrame、骨骼精调、原生接口指纹和私有 ImGui 绘制。石头预测与行为预测为独立总开关，石头只定向读取已发现候选，不因本功能启用50 ms全量战斗采样。

准星、墙面喷漆、石头落点使用独立射线 Binding，错误状态与地图重置互不牵连。保留 DXVK 使用的画面备份/恢复与菜单关闭时 overlay 绘制入口，不在 Source 模型 Hook 中发起 GPU 调用。

实体目录同时保留 weaponParent 与 thrower，基本可见性/碰撞数据不依赖行为预测。旧配置的正式命名空间各自保存，不把旧刀石/demo 开关迁移为已开启功能。

修正石头缓存落点与新轨迹采样时间不同导致的截线折返：落点秒数换算到当前采样基准，过期或已越过的缓存交点不再使用。只有有效飞行轨迹/交点时才请求石头 overlay，避免持有或失效记录持续触发画面备份。

遵循当前对话已确认的安装包布局：根目录只有 bin/ 与 README.md，许可证在 bin 内；不采用 rock 分支设计文档中曾提到的根目录 docs/、licenses/ 布局。完整对应源码另外打包。main 当前树只保留源码/文档，不加入安装 ZIP 或 DLL。

## 实测关注点

1. 菜单出现石头预测独立入口，所有功能总开关关闭；行为预测原有条与样式、红线默认设置保持。
2. 对 Tank/Spitter/Witch/Charger、求生者与道具识别，检查本体/爪子候选和本机手持；分类页和识别页开关一致。
3. 形变大小、XYZ、128/256、关闭还原，及原版/MOD 模型。
4. Tank 范围内红线，红底/填充/描边按需单独测试，多 Tank 独立提醒。
5. 石头持有不显示飞行轨迹；抛出后轨迹和真实接触标记，多个石头、开关外观、Esc/恢复、切图/断开。
6. 同时开启行为预测、石头、形变和喷漆后检查菜单、遮挡及稳定性；P2P 保持关闭。

石头仍是固定模型预测：重力320、假定箱半尺寸16。没有保证动态碰撞、网络时序和可见模型边界完全一致，落点圆不代表伤害半径。新整合版的离线测试与编译不能替代实机测试。

用户已确认整合测试版验收通过，并授权发布0.8.0正式版。正式发布仅更新版本标识、文档和发布流程，不改变已验收功能逻辑。

## 本轮验证结果

28组原生 ASan/UBSan 测试通过，覆盖双方模块、设置默认/往返、菜单导航、石头生命周期与接触预测、缓存时间换算、识别身份和旧功能回归。Windows x86 交叉构建通过。安装包需检查 ZIP CRC、bin/与README.md根布局、默认总开关、实际DLL版本以及对应源码提交。以上不替代实机验收。

## 正式构建

正式版通过 GitHub Actions 从v0.8.0源码标签编译，执行回归、构建x86 DLL、生成安装包与匹配源码、校验后更新zip并创建Release。已验收测试包不直接改名为正式包。CI触发后不等待或轮询结果，由用户通知完成。
