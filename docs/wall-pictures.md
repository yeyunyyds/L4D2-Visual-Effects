# 自定义喷漆：0.7.2-test

默认只在本机绘制；联机实验开启后分发给双方白名单中的本插件用户。安装、设置和 JSON 示例见 [README](../README.md)。

## 线程和渲染

菜单 / T 键发布请求 → 后台扫描 images、WIC 解码 → Source View_Render 执行 TraceRay 和九点支撑 / 五点世界遮挡检查 → 不可变场景快照 → D3D9 Present 在自建 BeginScene / EndScene 内上传纹理并绘制。

文件和网络 IO、PNG 编码、SHA-256 留在后台；所有引擎墙面查询留在 Source 回调。请求绑定地图代次并在两秒后过期。TraceRay 复用 DangoMusic main 54ed404 的已验证构建配置，完整 engine.dll SHA-256、PE、对象 / 虚表和代码样本通过才调用。

投影改为齐次空间 Sutherland–Hodgman 裁剪，裁剪近 / 远 / 左 / 右 / 上 / 下平面和正 w，并插值 UV 后以 triangle fan 绘制。单角越过相机或近裁剪面不再整张拒绝。仍以地图代次、正面、350ms 可见性租约和五点世界采样判断是否显示；每 50ms 按图片总量分配检查预算。部分墙体遮挡仍保守隐藏整张；当前不使用场景深度，动态实体 / 手部仍可能被图片覆盖。

WIC 解码最长边 2048，预乘 BGRA；纹理按二次幂填充并修正 UV，ONE / INVSRCALPHA 混合。0.7.1 的场景 GPU 回调与深度借用在 DXVK 下出现用户报告的闪烁 / 崩溃，0.7.2 已全部撤回。Source 回调只负责快照、射线和实体数据，不接触 D3D9；GPU 操作集中在既有 Present / Reset / deviceCreated 生命周期中。Present 备份 / 恢复背缓冲，单独 BeginScene / EndScene，ZENABLE=FALSE，不读取或依赖引擎深度表面；完整还原状态。设备丢失跳过覆盖绘制，Present失败不继续拷贝恢复。

目前未解决手部深度遮挡，禁止把回退描述为正确世界层 decal。按Esc自动暂停喷漆显示，保留放置记录；关闭游戏界面后需在本插件菜单“恢复喷漆显示”手动恢复，避免用错误的鼠标标志猜测游戏UI状态。

Reset / ResetEx / 新设备前释放默认池资源，图片绘制完整还原 D3D9 状态。

## 大小、输入和数量

默认长边 60，旧全局尺寸迁移减半一次，以 sizeProfileVersion 标记。wallPictures.sizes 按文件名保存长边；“应用所有”清除覆盖并改统一默认。设置快照变化后重新调整自己已喷图片的矩形，保留中心 / 比例 / 朝向，重新检查墙面支撑；不支持的扩大操作保持原尺寸。对方图片的尺寸由发送方控制。旋转 / 透明度仍用于后续喷漆。

T 键在 Present 轮询前台游戏窗口的按下沿，不修改或吞掉游戏按键；500ms 防连发。菜单、失焦、标准 Y/U 聊天和控制台输入时抑制；不再根据系统CURSOR_SHOWING阻止T，避免DXVK中鼠标标志与游戏光标不一致。前台窗口按根窗口匹配，并支持swapchain窗口和同进程前台回退。控制台键可切换进入 / 退出状态，Enter或Esc结束聊天。自定义聊天键、第三方输入 UI 无法完整识别，默认关闭此绑定。自动下一张只在成功放置后切换，按目录排序循环。

数量默认每人 2、可调 1～8，超出删除同一作者最早图片，减少上限也立即淘汰；撤销 / 清空只操作自己。全场上限32，达到时先淘汰远端旧图片。刷新 / 关闭模块 / 切图清理自己的图片，并经快照同步；关闭模块与退图清理整个本机场景。

## Steam P2P 实验

参考 [DangoMusic 一起听分支](https://github.com/yeyunyyds/LDBDangoMusic/tree/experiment/steam-progress-sync)，提交 6d327fcabe322771e5737165862a9db455998860。借用游戏 steam_api.dll 的用户 / pipe；不调用 SteamAPI_Init / Shutdown，不释放游戏用户、不消费游戏全局回调。保留显式 x86 SteamID 返回适配，使用 Legacy SteamNetworking006 / 005 可靠 P2P 和独立通道 **45632**；关闭时只关闭这个通道。

这是本插件自有 LVSP 协议（JSON app=LVSP、v=1），不兼容音乐状态协议。双方需要相同版本 L4D2Visual，不是仅安装 L4N。默认自动匹配：每秒在 Source 线程采集当前局真人名单，沿用 DangoMusic 的已校验 engine GetPlayerInfo RVA 0x5f4d0 / 144字节输出契约，以及 localPlayer / maxClients 调用；验证PE与函数字节，输出加哨兵，过滤机器人和TV、校验XUID/accountID。名单保鲜5秒，最多本机及三名其他真人。

后台从同局名单生成候选白名单和排序无关的 cohort 房间键，借用Steam身份必须与游戏本机ID一致。只向候选发送本插件hello，双方开启联机且协议 / cohort一致、nonce握手通过才传图片。成员变化 / 切图 / 名单失效清理连接并重新匹配。喷漆各作者独立发布，无需音乐房主选举；不与DangoMusic的45630发现协议混用。超过四名真人的服务器可能形成不同候选名单，需切到手动模式。

关闭自动匹配可沿用最多八个互相许可SteamID64和同room的手动模式，此时自行确保地图一致。自动模式无需填写ID或room，不会发现只装普通L4N的用户，也不扫描公网。

启动 / 地图 / 设置变化产生新 nonce。hello / ack 双向绑定双方 nonce；数据必须指向当前会话并来自白名单。state 按递增序号发送完整本地喷漆快照，含稳定作者内 ID、PNG 内容哈希和墙面矩形；新会话清理旧图片，超过10秒没有握手 / 数据清理对方。迟到的旧会话数据、倒退的快照会丢弃。图片不会转发给其他人。

只对已喷的自己图片编码 PNG，去除原文件名与元数据；尺寸上限保持2048。接收端按需发 need，发送方按1400字节分片、每个JSON包≤4096字节、每20ms最多16片分发。接收分片校验偏移 / 长度，容许乱序与重复；进度中断30秒淘汰。每个 PNG 最多20 MiB，全局最多两份接收缓冲且合计≤32 MiB；当前按需请求串行占用一个槽，避免多个对端同时挤满接收缓冲。完整 SHA-256 验证后由同一有界 WIC 解码器验证，再以纯哈希文件名写入 spray-cache/，不会使用远端路径或文件名。

磁盘接收缓存≤64 MiB，按需清理不再被远端快照引用的文件；重启联机或切图重新清理。编码缓存≤64 MiB，CPU / GPU 渲染缓存各≤64 MiB，这些是独立预算。屏幕备份不计入图片缓存。大图及多个对端会增加带宽和后台内存，不承诺FPS或秒级大图传输。

Source 回调只接收有界作者快照，再校验位置 / 正交单位轴 / 尺寸 / 支撑，避免网络线程调用引擎。删除、数量淘汰、大小修改以每秒快照同步；收到 PNG 后还要等待一次后台解码。接收者关闭联机后删除远端图片，保留自己的喷漆。

## 双客户端验收

本地十五组测试及 Windows x86 构建通过；近面裁剪、FIFO、多尺寸、合法 / 非法几何、分片乱序 / 重复 / 越界均有回归。本环境不能运行两个 Steam 游戏客户端，以下必须实机验收，不能把编译或协议单测当作 Steam 互传成功：

1. 两个不同 Steam 账号均装本版插件，进入同局，保持自动匹配开启；无需填写ID或room，开启模块 / 联机后双方握手数为1。玩家进出后重新匹配，机器人 / TV 不加入。另测自动匹配关闭时的手动名单。
2. A喷PNG、JPG、透明图片；B等传输后应显示相同位置、比例、旋转和透明度。随后B喷，A也收到。
3. A调整当前文件大小，B同步；A喷第三张，默认两张中最早一张在双方删除；撤销 / 清空 / 降低上限同步。
4. B晚加入应收到A当前图片；B关联机应只剩自己的图片；重开、断网恢复、切图后不得残留上一会话图片。
5. 不同对局、手动模式不同room、非候选 / 非白名单、只有普通L4N客户端均不显示；相同图片不重复传输，收到的图片不自动转发。
6. 近墙左右转头，部分出视野及近面相交时保留可见部分；背面 / 完全离开视野不显示。测试窗口切换、重置、其他渲染插件共存；当前仍可能盖住手部，这是已知限制；Esc后应暂停显示，需在插件菜单手动恢复。重点确认DXVK中喷图、旋转视角、切窗与退出不会闪烁或崩溃。
7. 标准聊天输入T不触发，T开关关闭时不触发；自动下一张只在喷成功后变化；逐文件大小及“应用所有”保存重启仍正确。
