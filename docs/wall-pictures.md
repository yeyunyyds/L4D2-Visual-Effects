# 本地图片挂画：0.6.0-test

模块仅操作本机文件、图片纹理和墙面查询，不上传、不分发、不改变原版 spray。其他玩家使用普通客户端时看不到。

## 数据流

菜单发布设置与放置请求 → 后台线程扫描 images / WIC 解码 → Source View_Render 回调执行墙面射线和支撑 / 可见性检查 → 发布不可变场景快照 → D3D9 Present 读取快照、上传纹理并绘制图片。

菜单与 Present 不读图片文件，Source 回调不解码图片；所有 TraceRay 调用留在已有 Source 游戏线程回调中。每个请求固定选择时的文件和参数，并绑定地图代次，超过两秒或切图则拒绝。

图片最长边解码为最多 2048 像素，保留透明度与比例。WIC 输出预乘 BGRA，与 D3D9 A8R8G8B8 / ONE + INVSRCALPHA 混合对应。GPU 纹理按二次幂填充并修正 UV；缓存限制计算包含填充尺寸。

## 放置与显示

复用 DangoMusic main 54ed404 的 wall_panel / source_trace_contract / source_walls 绑定信息。校验 engine.dll 的完整磁盘 SHA-256、PE、接口对象、虚表和代码样本后才调用 EngineTraceClient003::TraceRay[5]。

只接受世界墙面，拒绝地面 / 天花板、玻璃 / 天空等不适合的命中。墙面法线确定固定坐标轴，按图片比例创建矩形并应用平面内旋转；九点支撑检查用于拒绝跨墙角或不足以支撑矩形的位置。

可见性沿用五点世界射线采样，最多每 50ms 检查两张，单图可见性租约 350ms。地图或相机失效时清理，近裁剪面穿越和背面视角拒绝显示。此方法不是连续覆盖的证明，也不检查动态实体遮挡；部分遮挡会保守隐藏整张，不能等同原生 decal。

## D3D9 生命周期与开销

Present 在未修改的背缓冲上备份画面，提交挂画 / HUD，调用原 Present 后恢复背缓冲，避免交换链重用造成重影。备份表面按设备 / 分辨率 / 格式复用，不逐帧创建；没有可见挂画且菜单关闭时释放备份表面。

图片纹理首次需要时上传；删除 / 清空 / 关闭后剔除不用的纹理。Reset / ResetEx / 新设备前释放默认池纹理和备份表面，之后从 CPU 缓存重建。插件绘制 / 重置经递归互斥串行化，保留原回调链；图片绘制用完整状态块还原 D3D9 状态。

CPU / GPU 图片缓存各 64 MiB，源文件上限 32 MiB / 32MP，最多八张挂画。屏幕备份不计入图片缓存预算，可见挂画仍带来整屏复制与绘制开销，本版不承诺某个 FPS。

## 当前验收边界

本地测试验证路径 / 设置、比例 / 旋转、支撑拒绝、遮挡拒绝、数量上限、撤销 / 清空 / 切图、地图 / 时效租约、射线线框 ABI 和透视投影。Windows x86 交叉编译验证 WIC / D3D9 API 与导出。

当前环境无法运行 Windows 游戏；PNG / JPEG 的 Windows WIC 实际解码、透明边缘、渲染状态共存、窗口切换 / 设备重置以及动态遮挡均需要实机确认。图片不包含动画帧播放、EXIF 自动转向或跨墙角变形；可通过旋转控制手动调整朝向。
