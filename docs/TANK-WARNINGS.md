# Tank 攻击范围内提醒 · preview3

入口：**Tank 预测 → 攻击范围内提醒**。四项独立开关，均默认关闭；Tank 总开关继续默认关闭，原有显示偏好保持不变。

| 提醒方案 | 玩家进入范围后的表现 |
| --- | --- |
| 进度条红色与红底 | 条、边框变红，添加深红底；尚无冷却数据也显示红底 |
| 攻击范围红线 | 当前攻击扇区的圆弧、边界和刻度变红；前瞻虚线保持原色 |
| 攻击范围红色填充 | 当前扇区增加约19%不透明度的红色填充，先绘制填充再绘制线条与计时条 |
| 原生红色描边（实验） | 使用游戏原生 Glow 的 LOS 类型给该 Tank 红色描边；保留已有 Glow，不覆盖其他效果 |

可同时启用，也可逐项比较。条和范围提醒遵守对应的显示项开关及游戏画面暂停门控；描边遵守 Tank 总开关、画面显示、前台/暂停门控。菜单显示描边等待、已有描边或接口拒绝等状态。设置保存于 hud.json 的 tankPrediction.warnBar / warnRange / warnFill / warnOutline，旧配置缺少这些项时全部关闭。

## 判定与边界

检测实际本机玩家完整句柄，只对存活求生者生效；不使用相机位置、旁观对象、Tank 的索敌对象或其他求生者来代替本机玩家。不使用 Steam/P2P 玩家发现接口，P2P 保持原有默认关闭。

使用现有攻击范围：游戏运行时手长加 Tank 水平碰撞半径、当前朝向及运行时攻击角度。对玩家位置判断水平距离和扇区角度；双方碰撞高度可读时要求高度区间相交，否则以高度差不超过范围半径作近似过滤。与图示扇区一致，未额外扩展玩家水平碰撞盒。检测的是**当前实线扇区**，不是前瞻虚线，也不以进度条是否冷却完成作开关。每个 Tank 独立判断，离开其范围就恢复常规样式。

攻击参数、玩家健康、实体身份或新鲜快照缺失时停止提醒；切图、断线和句柄重用不沿用旧实体状态。范围只是客户端几何估算，不判断墙体遮挡，也没有保证真实出拳命中的能力。

## 原生描边的实现和验证

参考 Skeeto 同一 GPL-3.0 源码版本的 CampaignOutline* 路径，版权出处见 NOTICE.md。仅在描边提醒开启并运行时校验通过时调用原生函数：client.dll SHA256 必须为 c0a8e1e88f7312db11bcfd4b0ec574d224a34b2d9a615d6088b28335eeb4af1f，校验 SetGlowType（RVA 0x109a20）与颜色 RecvProxy（RVA 0x1098a0）的指令前缀，并校验实体完整句柄、嵌入式 DT_GlowProperty 布局及对象虚表。使用原生颜色代理同时刷新 RGB 缓存，不只写颜色字段。不新增模型重绘或渲染 Hook，不在 Source 模型 Hook 中调用 D3D。

只接管原本 Glow type=0 的实体，保存原值；离开范围、关闭功能或有效游戏帧中停止插件时，仅还原仍与本功能写入值一致的字段。切图直接丢弃旧代次引用。服务器或其他插件的已存在 Glow 会保留，可能导致该项没有红色效果，可用另两类提醒补充。第一次接管描边后将本 DLL 固定到游戏进程结束，更新需要完全退出游戏。总开关关闭时保留实体目录到还原完成，再停止浏览。极端情况下插件停止期间没有游戏帧，无法在游戏线程完成还原，会记录日志；请完全退出游戏再更新 DLL。

25 组 ASan/UBSan 测试覆盖距离/角度/高度边界、仅本机玩家、多人和多 Tank、冷却独立性、死亡/丢失/过期数据、默认关闭与配置往返、描边布局与逐字段归属、红底和近裁面/视野裁剪。Windows x86 交叉构建通过。原生描边和 DXVK 下红色填充尚需游戏实测。

建议按计时条、红线、填充、描边的顺序分别开启，测试走进/走出、Tank 转身、多个 Tank、楼层差、开关还原和切图；确认 MOD 与原版 Tank 表现。诊断功能没有加入正式配置。
