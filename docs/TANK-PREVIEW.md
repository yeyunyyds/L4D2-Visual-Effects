# L4D2Visual 0.7.3-tank-stopwatch-preview4

**L4N 客户端 Tank 行为预测实验；不是0.7.2正式版的替代稳定版。**

**免责声明：联机功能未经测试，不保障 VAC 安全。Tank预测也未经游戏实机校准，不能作为精确安全范围。**

本功能不依赖SourceMod、Left4DHooks、服务端插件或第三方扩展，只使用L4N插件自身已有的进程内采集和Present绘制。基础喷漆、T键仍保留0.7.2路径，不增加Source回调GPU操作。

## 观测计时 preview4：当前使用方式

本版以“观测出拳后的估算计时”为主，不再把AI的陈旧客户端时间戳显示成0秒真实冷却。仍仅需L4N，不使用SourceMod；不增加Source回调中的GPU绘制。

1. 进入Tank行为预测，开启功能及诊断记录。
2. **自动路径**：只有成功解析到明确拳击/melee/attack活动时才自动启动；同一动作的连续帧不会续秒，同序列循环需观察到cycle回绕。短暂解析未知不会当作新起手。**目前普通拳击可能仍位于未解析的共享动画或动画层中，自动识别不保证覆盖所有拳击。** 不会把Idle_Rage、距离接近或扣血强行当成一次出拳。
3. **人工校准路径**：开启菜单里的“F7手动标记出拳”（默认关），关闭插件菜单，看见Tank出拳起手时按一次F7。选择准星前方最接近视线、2048单位内的Tank；也可在菜单中使用每只Tank的“手动标记此Tank刚刚出拳”。标记只用于本地计时，不修改Tank。F7不吞掉游戏原有绑定，使用前确认没有冲突。
4. 读取当前tank_swing_interval与tank_swing_miss_interval；命中/挥空无法区分时使用较短间隔，提前提示可能恢复。未读取到正常间隔不启动；缺少挥空间隔时仅是普通间隔估算。零间隔按零处理，不代入固定秒数。
5. 自动起手发生在相邻采样之间，采用较早采样时刻作为计时起点，避免因观察延迟误报更长的冷却窗口；手动按插件处理标记时观测到的游戏时间起算，包含人的反应误差与采样延迟。观察到起手不证明该拳没有被打断。
6. 计时跟随实际推进的Source模拟时间；暂停/时钟未知不凭Windows时间继续倒计时。计时结束只表示“估算窗口结束，可能恢复”，不是保证AI能出拳，也不是安全区域。
7. **投石单独显示**：识别到投石时暂停拳击自动估算；动作结束后显示“距投石动作结束多久”，不把它当作恢复倒计时，不套用拳击间隔。人工明确标记出拳可覆盖当前动画状态供校准。

Tank上方小条：灰色未知，黄色自动动画估算，紫色人工标记估算；所有数值均在菜单标为“观测估算”。新日志schema=4的stopwatch记录source、eventId、startedAt、span、triggered、expired和投石结束时间差；即使采样错过单帧triggered标志，也可据eventId核对事件。原始客户端时间戳只留在诊断中，不作为主要冷却显示。

建议先做一轮**人工标记**校准：看见起手立即按F7，重复普通出拳、明确挥空、投石后出拳。再与自动事件对照，记录是否太早/太晚。没有动作来源和实际结果标注时，不能声称已测得准确率。

## 冷却 preview3 调整

本版只补充Tank实验的攻击计时读取，不引入SourceMod或新的游戏虚函数，不改正式版0.7.2的发布包。

- 读取已经在元数据中出现的零偏移嵌套表：bcc_localdata/DT_BCCLocalPlayerExclusive、LocalActiveWeaponData/DT_LocalActiveWeaponData，以及serveranimdata/DT_ServerAnimationData。分别尝试获取m_flNextAttack、m_flNextPrimaryAttack和m_flCycle；表名、类型不匹配时保持未知，不沿未知代理读实体数据。
- m_flSimulationTime的Recv类型可能是Int，但接收代理写入已解码FLOAT。本版只对这一已知属性按浮点读取并校验，再观察活跃角色的模拟时间是否实际推进。所有剩余时间计算使用同一个Source时钟，不用Windows开机时间减游戏时间，也不在游戏暂停时用墙钟强行倒计时。
- 同时读到且验证两个正时间戳时，显示较严格的客户端计时约束。只读到一项时，显示仍未结束的冷却下限；该项结束而另一项未知时，不显示“已经可攻击”。全零、缺失、NaN、异常未来时间、时钟不推进、武器句柄失效或归属冲突都显示未知。
- 菜单显示数值；Tank上方小条：灰色未知，黄色仅部分计时下限，青色为两项客户端计时均读到。**这不是AI攻击资格判定；零秒也不等于Tank下一帧一定能出拳。** 动画、技能和服务器规则仍可能限制攻击。
- 局部同步表可能仅向武器所有者发送数据。AI Tank字段在客户端可能长期为零或不更新，因此“能定位字段”不等于“已经得到准确AI冷却”。本地单人仍需实际验收。
- 诊断schema=3新增observedGameTime、clockSourceHandle/clockReason、weaponDeadline/actorDeadline、cooldownPartial/cooldownReason，以及武器归属。参数interval仍单独记录，不能把它当作实时剩余冷却。

建议开启诊断记录，连续录下至少数次普通挥拳、挥空及投石后的恢复。重点看计时条是否重新填充并随攻击变化，或菜单是否明确显示零值未同步/时钟停滞。新日志tank-prediction.jsonl用于确认实际可读性。

## preview2 调整

- 原版只从Engine模型回调观察动画；现在也在已有Studio钩子的关闭拉伸分支之前采集CPU元数据，补足可能绕过Engine回调的快速绘制路径。不新增Source/GPU回调，不改变骨骼或调用新的游戏虚函数。
- 瞄准近乎竖直时，水平yaw没有可靠的地面方向含义。此时不标为可能锁向，也不画水平参数范围；方向线保留实际pitch。
- 新日志schema=2包含pitch、动画观察路径和拒绝原因、当前参数计时、元数据字段提示，以及actor/result各自时间，便于定位unknown动画和缺失冷却。字段提示只读取表结构，不把未知数据代理当作实体偏移。
- 定向采集只选角色/Tank和其武器，排除CCSTeam等非角色团队对象。

## 安装和启用

1. 退出游戏，备份现有 `bin/neko/plugins/L4D2Visual.dll`，将安装包的bin合并到游戏目录，确保只加载一份。
2. 优先在本地单人地图测试AI Tank。通过L4N打开本插件，进入 **Tank行为预测（实验）**。
3. 功能默认关闭；开启 **Tank预测**，可独立切换线条绘制、诊断记录和预测时间（0～500ms）。
4. 按 `- / =` 翻页，`0`返回。开启后等1～2秒让实体和动态参数完成首次读取。
5. 保留其他默认设置即可；不需要开启拉伸或联机。正式版0.7.2的配置可继续使用，实验功能默认不会自行打开。

## 本版实际能做什么

- 启用后每200ms沿原有实体采集发现对象，额外每50ms只更新已发现的Tank、求生者及其手持武器（最多32个记录），校验完整实体句柄与序列号。
- 优先读取RecvTable中的瞄准角；缺失时退回身体角，并明确显示低置信度。两者不能混为一谈。
- 尝试读取 `m_lookatPlayer`，标为 **注视目标（非锁敌保证）**。若存在可用的 `m_hEnemy` / `m_hAttackTarget` 网络字段，另标为 **网络敌对目标**。句柄必须解析到当前活着、非休眠的求生者；字段不可用时才采用朝向推测，有歧义则显示未知。
- 根据瞄准角变化和目标相对方向识别“朝向停滞：可能锁向”。这不等于已经证明是投石锁向。
- 通过既有模型回调只读解析Studio模型的当前基础动画标签，尝试识别投石/攻击动作；未硬编码动画编号。不读取不明确的代理动画层，无法识别时显示unknown。
- 若可读，显示武器/角色下一次攻击时间与角色模拟时间的差值。这是估计计时，不是精确服务器冷却证明。
- 在可识别的x86 ConVar内存对象中只读获取 `tank_swing_range`、`tank_swing_arc` 等当前值，校验名称、父对象、复制标志、数值范围和字符串/浮点一致性，不调用新的游戏虚函数。
- 本地单人可以额外尝试同进程server.dll的参数对象，无该模块则尝试客户端复制参数。模块存在本身不证明正在本地开服；此处只校验ConVar当前值，不读取AI私有状态。不注入服务端插件，不访问远端服务器内存。
- 参数获取失败或过期时明确显示未读取，**不偷偷代入固定手长**。每500ms更新当前数值，未找到时每10秒重新扫描。

## 线条含义

- **青色短线**：可读瞄准方向；灰色表示仅有身体朝向。
- **黄色范围线**：运行时距离 + Tank可读碰撞半宽的参数估计区，角度暂按运行时arc参数解释，**参数语义和实际命中算法仍需校准**。不包含完整服务器碰撞、延迟补偿和目标碰撞盒计算。
- **蓝色虚线**：按最近移动速度和平滑时间推算的位置对应区域，不预测真人下一次按键或AI未来决策。
- **目标连线**：橙色为可读网络敌对字段，黄色为注视/推测；请在菜单核对来源，不要把注视线等同于真实AI锁敌。

本版不会因“刚丢石头”而凭空缩短距离或缩小扇区。若攻击方向暂时停滞，方向线和区域会保持该方向；此时可观察目标从侧面经过时的实际挥空。

线条使用已确认基础可用的Present路径，不借用场景深度，会有遮挡局限。沿用Esc暂停显示，返回游戏后在自定义喷漆菜单恢复显示。

## 建议的本地单人验收

1. 开启预测和诊断记录，等Tank出现，确认菜单里能否读取距离/arc、瞄准角、动画标签及注视目标。
2. 分别测试未投石直接接近、投石后从正前方/左右侧/后方经过，记录命中或挥空，以及注视目标是否跟随。
3. 多名求生者时让不同角色交替接近、诱导Tank换目标，核对注视线与实际追击对象。注视与追击不一致也应记录，这正是需要区分的数据。
4. 改变移动方向、跳跃和上下坡，观察预测。远端服务器、多种Tank模型/插件服需要单独验收。

诊断日志：`bin/neko/plugins/L4D2Visual/tank-prediction.jsonl`，每100ms最多一条；约4MiB轮转到 `tank-prediction.previous.jsonl`，两份可压缩后提供。包含当前参数、Tank朝向、动画、目标来源、求生者位置/血量和可读计时，便于对照投石与挥空。日志不会记录完整聊天或SteamID。

**本环境无法运行Windows游戏；模拟回归和x86编译不能证明实机字段都可读，也不能证明命中预测已达到高准确率。** 若动态参数显示未读取，只有方向/目标采集有效，不会画出伪造距离。
