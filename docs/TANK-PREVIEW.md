# L4D2Visual 0.7.3-tank-events-preview6

Tank 客户端动画事件诊断预览，仅依赖 L4N。正式版仍为 0.7.2。

**联机功能未经测试，不保障 VAC 安全。**

## 本次用途

preview5 已在实际客户端确认 `CTEPlayerAnimEvent` 及三个字段。本次开始观察该类的事件工厂与字段接收代理，记录实际收到的玩家句柄、事件编号和附加数据。

这是诊断 Hook：临时替换该类注册的四个回调指针，原回调以原参数执行一次，原工厂返回值原样交还。不会主动调用未知实体虚函数、事件工厂或游戏攻击函数，不更改接收值，不注入攻击事件。关闭 Tank 预测或诊断后在下一游戏帧恢复原回调，卸载时也尝试恢复。

**仅同时开启 Tank 预测与诊断记录时接入**，两个开关均默认关闭；已保存的开启设置仍会读取。仅绘制预测而未开诊断时不安装此事件 Hook。P2P 默认配置不变。正式版不包含本次变化。

绑定前检查 client.dll 文件哈希、描述符、静态单例工厂、已验证布局的微型 getter、字段名称/类型/偏移及原代理地址。任何检查失败都不接入并记录原因。不会套用 SDK 的事件虚表回调槽位。

## 安装与测试

1. 完全退出游戏，将压缩包中的 `bin` 合并到游戏根目录，替换插件 DLL。
2. 在本地单人开启“Tank 行为预测”和“诊断记录”。不需要 F7 或人工标记。
3. 让同一只 Tank 普通挥拳、挥空、投石后再挥拳，约 20～30 秒，随后退出游戏。
4. 提供 `bin/neko/plugins/L4D2Visual/` 中的以下文件：
   - `tank-animation-events.jsonl`：独立事件记录；没有接收到事件时可能不生成。
   - `tank-animation-binding.json`：绑定结果与入口代码诊断。
   - `tank-prediction.jsonl`：schema 6 的状态记录，包含回调计数与最近事件。
   - 同名 `previous` 日志若存在，也请保留，避免漏掉较早的攻击片段。

## 如何解释记录

`eventCapture` 会区分工厂调用次数、三个字段的接收次数、无效样本和队列丢弃数。事件文件记录 `raw` 与 `decoded`（顺序：玩家、事件、附加数据），以及 `factoryBoundary`、字段 `mask` 和 `complete`。

只有观察到工厂边界且三个字段均收到的组才标为完整；不完整记录保留，但不可靠关联为某个玩家的新事件。相同事件编号反复出现仍分别记录。只用新鲜实体快照中的完整句柄进行玩家类别关联，无法关联则保持未知。

33/34 仅按公开资料标为候选手部攻击事件，尚未验证 AI Tank 是否发送这些编号、是否有重复或缺失。本次不将其接入冷却估算，也不能保证每次挥拳都会被捕获。没有事件时不能据此断言 Tank 没有出拳；引擎可能缓存了回调入口，或使用其他动画路径。

保留所有叠加动画层采样，并补充 v48 模型中的 included model 名称。**共享模型的全局序列映射仍未实现，序列 80 仍不能命名为拳击。**

## 安装包结构

根目录只有 `bin/` 和本 README。许可证位于 `bin/neko/plugins/L4D2Visual/licenses/`。退出游戏后可换回正式版 0.7.2 的 DLL。
