# L4D2 Visual Effects

**求生之路 2 视觉效果插件 · 开发测试版 0.5.3-test / 正式版 0.4.0**

基于 **L4N v2 / Windows x86** 的求生之路 2 视觉效果项目。当前实现周期性竖直拉伸。0.5.0-test 将目标选择扩展为 **Class ID 类别开关**，默认所有类别关闭，并支持 128 / 256 骨骼容量运行时切换。具有双脚的模型保留脚部及脚趾姿态；其他受支持模型以渲染根骨骼为锚点。效果在绘制阶段使用骨骼矩阵副本，不写入实体位置、碰撞边界或命中骨骼缓存。

项目名称为 **L4D2 Visual Effects（求生之路 2 视觉效果）**，覆盖项目整体的视觉效果方向；拉伸是当前实现的功能。插件标识、游戏内菜单、DLL 和安装包使用 `L4D2Visual`。

## 安装与启用

1. 准备已安装 **L4N v2** 的 Windows x86 游戏环境。游戏构建必须匹配 [render-profile.json](docs/research/render-profile.json) 中记录的 `client.dll`、`engine.dll`、`studiorender.dll`。
2. 完整退出游戏，解压所选版本安装包，将 `bin` 合并到游戏根目录。确认插件位于 `bin/neko/plugins/L4D2Visual.dll`，且只加载一份。
3. 启动游戏并进入地图，在 **L4N → L4D2Visual 0.5.3-test → 实体分类** 中开启需要的角色或类型，再返回主菜单开启 **拉伸总开关**。正式版 0.4.0 沿用原特感开关。
4. 进入 **动画预设与细调** 调整效果；使用 **保存设置** 保存动画参数、类别规则、骨骼容量、渲染模式与菜单外观。
5. 关闭拉伸后检查外观恢复。更新或移除插件前完整退出游戏，不要运行时卸载。

拉伸开关默认关闭，且不跨游戏会话保存。卸载时删除该 DLL 即可停止加载；配置与日志保存在同目录下的 `L4D2Visual/` 文件夹，可按需备份或删除。

## 实体分类与识别（0.5.3-test）

入口：**实体分类**，按 **特感、求生者、场景可拾取武器与物品、手上道具、其他** 整理类别。使用 **`- / =`** 翻页，`1～9` 选择，`0` 返回；方向键只在菜单位置编辑器中移动面板。

- **特感固定列出八种实际类型：Smoker、Boomer、Hunter、Spitter、Jockey、Charger、Tank、Witch。** NPC 依网络类型识别，感染者玩家以队伍和 `m_zombieClass` 区分；不同特感共享玩家 Class ID 时仍可独立开关。
- **求生者固定列出八人：Nick、Rochelle、Coach、Ellis、Bill、Zoey、Francis、Louis。** 每个角色独立开关，同时作用于该角色的真人和机器人，不因共享 Class ID 而联动；分类的全开 / 全关仅设置这八名角色。旧版类别规则作为默认值，单角色设置优先并可保存。
- 采用 DangoMusic 的固定类型目录思路，**八种特感始终完整列出**，求生者、可拾取物和手持模型等已知类型也无需刷出即可设置。开关按网络类型名称保存，实体出现后自动按其真实类型生效，不猜测或伪造 Class ID。
- 每个分类内提供 **开启本分类全部实体 / 关闭本分类全部实体**，分类规则也适用于后来识别到的新类别。单独 Class ID 开关可覆盖分类规则；再次批量设置该分类会清除该分类的单项覆盖。
- 除求生者角色和特感类型外，其余项目仍按 **Class ID** 生效，例如垃圾桶若属于 `CPhysicsProp`，其类别开关也会影响其他同 Class ID 道具。
- 保留 **一键全部关闭（含实验）**，同时清空类别 / 分类规则、关闭范围实验和拉伸总开关。所有类别在新配置中默认关闭，原有已保存的单项规则继续兼容。
- **手动识别与开关** 是独立页面：进入后选择手动识别，核对显示的名称与 Class ID，再明确选择 **开启该类别 / 关闭该类别**。进入页面和识别动作均不自动改变实体规则。也可将识别结果选作范围实验的触发类别。
- 识别复用 DangoMusic 的视角 / 距离排序，不是精确碰撞射线，不检测墙体遮挡；操作前请核对显示结果。
- 预定义目录外的扩展类型可由实体识别、ClientClass 链表和保存规则补充。菜单不展示实例列表，也不要求目标当前在场。求生者通过队伍与 `m_survivorCharacter` 识别，不把同 Class ID 的感染者玩家当成该角色；其余类型沿用原有开关规则。
- 可列出或识别不等于可变形。仍要求有效模型索引、实体关联及已接入的 Studio 骨骼绘制；静态地图物件、BSP、无骨骼模型与未接入的批量路径不保证覆盖。

## 实验：实体进入目标范围（0.5.2-test）

入口：主菜单 **范围实验**，**默认关闭**。

1. 选择作为范围中心的目标类型，默认 **Tank**。所有预定义类型均可直接选择；也可使用上次手动识别的 Class ID。
2. 调整半径，默认 **500 游戏单位**；范围 **100～5000**，支持 **±100 / ±10**。
3. 开启实验。首次手动开启实验会同时开启拉伸总开关；总开关仍可暂停全部效果。
4. 对每一个可处理实体，分别计算它与任一有效 Tank（或所选类型）的三维距离。**只有范围内实体参与拉伸，范围外实体保持关闭。** 多个范围中心取并集，Tank 自身距离为零。

例如半径 500 时，同一类道具 A 距 Tank 200、道具 B 距 Tank 800，仅 A 拉伸。玩家站在 Tank 旁边也不会开启 B；玩家离得很远也不会阻止 A 拉伸。玩家、镜头和观战位置均不参与距离判断。

实验开启期间使用上述范围过滤；即使手动类别设为开，范围外也不拉伸。**关闭实验**后恢复原先的手动分类规则，实验不改写这些已保存开关。没有有效范围中心时，不会退回全局拉伸。

手持模型、已识别的持有武器 / 物品及其可关联附件仍排除。**普通感染者默认排除**，可通过独立开关允许参与。普通感染者身体变形而独立衣物保持原样的问题尚未修复。

位置来自可验证的网络世界姿态，按约 200ms 的实体快照更新，不检查视线或墙体遮挡。已知死亡、休眠、隐藏、过期或其他地图的范围中心不生效。范围覆盖仍受模型身份、骨骼容量与绘制路径限制。

通过 **保存设置** 保存半径、中心类型、实验开关与分类规则。拉伸总开关仍不跨会话保存；重启后需重新开启总开关。

## 骨骼容量与渲染模式（0.5.0-test）

入口：**性能与兼容**，可在游戏运行时调整，并通过 **保存设置** 持久化。

| 设置 | 行为 |
| --- | --- |
| 骨骼上限 128（默认） | 使用 128 容量的缓冲；模型超过 128 根骨骼时保持原始绘制，不截断骨骼 |
| 骨骼上限 256 | 允许处理最多 256 根骨骼，供已扩展游戏骨骼上限的环境使用；此选项本身不修改游戏上限 |
| 完整兼容（默认） | 有已选中模型实体且效果开启时，临时关闭 `cl_modelfastpath`；停用、无目标或退出地图时恢复 |
| 保留快速路径（实验） | 释放插件对该变量的控制，保留游戏 / 用户的原始设置；部分可见主模型可能没有拉伸 |

切换从后续绘制调用生效，正在执行的绘制保留自己的缓冲容量。两种骨骼容量都只读取和变换模型实际骨骼数；不对引擎骨骼缓存原地操作。

快速模式用于覆盖与性能对比，**尚未接入完整批量绘制接口**，不能视作在完整覆盖下解决了快速路径开销。[优化实现与验证边界](docs/optimization.md) 说明了已完成项目和待验证部分。

## 动画设置

默认使用**平滑往复，周期 0.5 秒，竖直比例 0.5～1.1**。X/Y 不变，所有目标共用时间基准。

| 设置 | 行为 |
| --- | --- |
| 动画预设 | 平滑往复、Q 弹回弹、双跳脉冲 |
| 往复周期 | 每次调整 0.1 秒；范围 0.1～10.0 秒，越短越快 |
| 最小 / 最大比例 | 分别每次调整 0.1；总范围 0.1～3.0，上下限至少相差 0.1 |
| 恢复动画默认 | 恢复平滑往复、0.5 秒、0.5～1.1 |
| 保存设置 | 保存到 `bin/neko/plugins/L4D2Visual/hud.json` |

切换预设保留当前周期与比例；所有曲线限制在设定上下限内。修改参数会重启本轮周期。首次迁移旧配置时使用新的动画默认值并保留菜单外观，之后保存的自定义动画参数会正常恢复。

## 菜单操作

复用 DangoMusic 的原生 HUD 与 ImGui/D3D9 后端，L4N 提供菜单入口。

- `1～9` 选择，`0` 返回，`Esc` 或 `/` 关闭，`-` / `=` 翻页。
- 菜单外观支持背景预设、透明度、字号、位置和可选 F10 开关。
- 外观与动画参数通过主菜单的 **保存设置** 持久化，拉伸开关仍默认关闭。
- **接口与日志诊断** 显示实体关联、引擎 / Studio 回调、已拉伸绘制及日志写入状态。

## 目标与工作方式

0.4.0 正式版以特殊感染者为目标；0.5.0-test 使用上述 Class ID 选择规则，对具有有效模型身份的已选类别尝试绘制变形，不按模型路径限制类别。
绘制关联检查完整实体句柄、当前模型索引、renderable、Studio header、地图代次、休眠状态与快照时效。未知构建、过期目标、无效骨骼或无效模型身份时保持原始绘制。

从实际渲染骨骼生成独立矩阵副本，沿 Z 轴缩放后，对具有完整双脚识别的模型恢复双脚及其后代（含脚趾）的完整原始矩阵，再交给 Studio DrawModel。原引擎 DrawModelExecute 保留原始参数，不修改共享骨骼；这不额外提供 IK 求解。骨骼名称、层级与脚部索引按模型缓存，切图或模型头部变化时重建，缓存上限 64 项。

## 兼容性与验证边界

用户已在游戏中确认兼容路径有可见效果，并反馈 0.4.0 帧率有所改善；目前没有量化 FPS 对比数据。离线 ABI 核对、Linux 回归与 Windows x86 交叉编译已在此前发布流程通过，具体历史见 [验证记录](docs/validation.md)。

- **游戏构建限制：** 校验三个游戏 DLL 的磁盘完整 SHA-256；不同构建拒绝启用。已有绘制回调会保留并串接，但其他渲染插件组合仍需实测。
- **渲染开销：** 完整兼容模式有已选中目标且启用时暂时将 `cl_modelfastpath` 设为 `0`，覆盖可见主模型；关闭或退出地图时恢复。若用户期间主动更改该值，恢复逻辑保留用户的新值。该设置不写入游戏配置，常规绘制路径仍可能增加开销。
- **模型限制：** 0.5.0-test 对无完整双脚的模型使用根骨骼锚点；骨骼元数据、层级或矩阵无效时跳过。模型替换可能改变脚部权重，脚与腿的蒙皮过渡需实测。
- **画面边界：** 不走 Studio DrawModel 的批量绘制可能保持原样；不扩大渲染裁剪边界。大比例下的裁剪、LOD、阴影和光照一致性仍需验证。
- **碰撞与命中：** 实现不写入相关数据；实际游戏行为仍需与关闭拉伸时做对比，不能把离线检查等同于完整实机验收。

## 排查无效果或异常

1. 确认只加载了一份对应版本 DLL，进入地图后在分类菜单选择需要的角色或类型，再启用拉伸，等待至少一秒。
2. 查看 **接口与日志诊断**：关联次数为 0 与关联成功但绘制为 0 属于不同阶段的问题。
3. 查看 `bin/neko/plugins/L4D2Visual/L4D2Visual.log`。日志自动启用，含版本、接口校验、目标分类、模型绘制统计和姿态拒绝原因；启用时每两秒记录状态，避免逐帧写文件。
4. `fastpath=0` 表示兼容路径生效，`-1` 表示该变量未通过验证。构建校验失败时先核对游戏 DLL，不要跳过校验。
5. 复现后关闭拉伸，提交日志、游戏构建、其他渲染插件列表与画面现象。无日志时检查 DLL 加载情况及目录写权限。

## 开发、测试与打包

使用 C++17。Linux 回归需要 `g++` 与 ASan/UBSan；Windows x86 交叉编译需要 `i686-w64-mingw32-g++` 及 Windows/D3D9 开发库。

```sh
git clone --branch main https://github.com/yeyunyyds/L4D2-Visual-Effects.git
cd L4D2-Visual-Effects

# 十组本地回归；受限运行器中可单独关闭泄漏检测
ASAN_OPTIONS=detect_leaks=0 bash scripts/test.sh

# Windows x86 DLL，可用 CXX_X86 指定编译器
bash scripts/build-mingw.sh

# 生成 build/L4D2Visual-0.5.3-test.zip（DLL + 对应完整源码）
python3 scripts/package.py

# 可选：使用自己合法持有的游戏 DLL 进行离线构建核对
python3 scripts/verify_render_profile.py \
  --client /path/client.dll \
  --engine /path/engine.dll \
  --studio /path/studiorender.dll
```

`CXX` 可指定本地测试编译器。不要把游戏 DLL 或用户 `hud.json` 提交到仓库。构建结果写入被忽略的 `build/`，发布时将安装包单独提交到 `zip`，不要合并下载分支到 `main`。

```text
src/       插件入口、动画、绘制关联、骨骼处理与诊断
vendor/    DangoMusic、L4N SDK、ImGui 等依赖及声明
tests/     动画、设置、菜单、骨骼姿态与拉伸回归
scripts/   本地测试、交叉编译、打包及 PE / ABI 校验
docs/      验证记录与渲染接口研究
```
